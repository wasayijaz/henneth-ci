# Henneth AI — Productization Roadmap

From a personal desk to a subscription research product. Status: PLANNING. Written 2026-07-14.

The desk today is **single-tenant**: `state/` is one owner's truth, generated by free/cheap loops and
served static from GitHub Pages. To become a paid product, layer a thin per-user tier on top of the
**shared** data + analysis engine — the expensive, differentiated part stays shared.

---

## What's already the moat (keep, don't rebuild)
- Shared **data + analysis engine**: prices, quant, 52 backtested strategies, 4-method fair value,
  **plain-English scorecards** (`score_fundamentals.py`), risk profiles, geo-risk, macro.
- **Explainability** — the real consumer edge. Retail PSX users don't want raw RSI; they want
  "is this company healthy, is the price reasonable, what changed this week." We already answer that.
- **The Desk Room** (analyst debate) + **accountability** (persona & broker leaderboards, scored calls).
- **Rule-5 culture** (research not advice, losses documented) — makes a public track record credible.

## What's missing for multi-user (the build)

### 1. Multi-tenancy + auth (the foundation)
- One **shared** data/signal layer (unchanged). A thin **per-user layer**: watchlists, saved
  tickers, portfolio (manual entries — desk never executes), alert preferences, plan tier.
- Needs a real backend + auth. Cheapest fit: **Supabase** (Postgres + Auth + Row-Level Security,
  generous free tier) — was already evaluated for storage. Per-user rows keyed by `auth.uid()`;
  the shared `state/*.json` stays a read-only CDN artifact everyone reads.
- The static site becomes an app: anonymous users see the shared research (SEO + funnel); signed-in
  users get watchlists/portfolio/alerts; paid tier unlocks the premium layers.

### 2. Delivery (Telegram doesn't scale to paying users)
- **Email digests** (daily/weekly per user prefs) + **in-app** notifications are the standard.
  A weekly "what changed on your watchlist" digest is the retention engine.
- Cheapest: Supabase edge function + a transactional email provider (Resend/Postmark free tier).
  Keep Telegram as an optional power-user channel, not the product.

### 3. Explainability UI (the consumer product — lead with it, not signals)
- Elevate the plain-English layer: per-ticker "**Is it healthy? Is the price reasonable? What
  changed this week?**" as the FIRST thing a user sees, scorecards front-and-centre.
- The one real data gap to close: **multi-year financial trend charts + a company description**
  (needs a fundamentals-history scraper — flagged repeatedly). This is what "made easy" needs.

### 4. Public track-record page (best marketing asset)
- Public, timestamped, **including losses** — the persona + broker leaderboards already do this;
  make one of them the marketing hero. "Here's every call we made and how it did" is the pitch.

### 5. Billing
- Stripe (or Paddle for Pakistan/tax). Plan gate in the per-user layer. Free tier = shared research
  + one watchlist; paid = alerts, digests, Desk Room depth, full history.

## Compliance stance (must be everywhere — SECP-sensitive)
- Describe the product **only** as a **research & analytics tool**, never an adviser.
- **No per-user recommendations, no guaranteed returns, no performance promises.** Every number is
  educational information. Losses shown, not hidden.
- Persistent disclaimers: a **platform-wide footer** + a **topbar "Research · not advice" badge** are
  now on every page; the ticker/value/scores pages carry their own explicit callouts. Any email/digest
  must carry the same footer. Before charging anyone, get a Pakistani lawyer to confirm the
  research-tool framing keeps it outside SECP investment-adviser licensing.

## Build order (each ships independently; the desk keeps running)
1. **Hosting move** (prereq for private code — see below) + Supabase project + auth.
2. Per-user layer: watchlists → portfolio → alert prefs (RLS-scoped).
3. Email digests (weekly "what changed").
4. Explainability-first ticker view + the fundamentals-trends scraper.
5. Public track-record hero page.
6. Stripe billing + plan gates.
7. Lawyer review, then launch.

## Going private (the code) without taking the product down
Making `github.com/wasayijaz/psx-trade-desk` private is right for a paid product — BUT **GitHub Pages
does not serve a private repo on the Free plan**, so flipping visibility now would take the live site
**offline**. Options, cheapest first:
- **Move hosting to Vercel or Netlify** (free tier serves a PRIVATE repo, better for a real app anyway;
  keeps the site public while the code is private). Then make the repo private. **Recommended.**
- **GitHub Pro** (~$4/mo) enables Pages on a private repo (site still public). Smallest change.
- Note: making the SITE itself access-controlled (not just the code) needs a real app/auth layer
  (item 1) — Pages/Vercel static hosting is public by URL regardless.
